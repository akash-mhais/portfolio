01_System_Architecture

EMO Robot is built around a Raspberry Pi 3B+ acting as the central compute node. It orchestrates concurrent processes for display rendering, servo motor control, sensor polling, and audio playback using Python's multiprocessing module.

developer_board
Processing Core

Raspberry Pi 3B+ runs the main Python application, leveraging multiprocessing to achieve real-time parallelism between the display pipeline, motor control, and sensor interrupt handlers.

# Concurrent Process Spawning
p1 = multiprocessing.Process(target=check_sensor)
p2 = multiprocessing.Process(target=show, args=('happy',4))
p3 = multiprocessing.Process(target=sound, args=('happy',))
p4 = multiprocessing.Process(target=happy)
hub
Communication Bus

The system utilizes three distinct communication protocols to interface with peripherals:

SPI — LCD Display (40MHz clock)
I2C — PCA9685 Servo Driver
GPIO — Touch (BCM17) & Vibration (BCM22)

// Concurrency_Model

The application uses Python's multiprocessing with a shared Queue and Event system for inter-process communication. The sensor process runs continuously and pushes detected emotions into the queue, while the main loop renders the appropriate animation, plays sound, and executes the matching servo routine in parallel.

sensors P1: Sensor Always Running
display_settings P2: Display Frame Renderer
volume_up P3: Audio WAV Playback

Servo Articulation Map

Three SG90 servos driven via PCA9685 I2C expander. Each servo maps to a unique axis of motion on the robot body.

servoB — Channel 13
Base Rotation • Reference at 90°
Motion Profiles

Each emotion maps to a specific combination of servo movements. The arms move symmetrically (mirror-linked), while the base provides rotational expression.

# Happy — Energetic wave pattern
def happy():
    servoMed()  # Center all servos
    for n in range(5):
        for i in range(0, 120):
            if i <= 30:
                servoR.angle = 90 + i  # Up
                servoL.angle = 90 - i  # Up
                servoB.angle = 90 - i  # Rotate
            if (i > 30 and i <= 90):
                servoR.angle = 150 - i # Down
                servoL.angle = i + 30  # Down
                servoB.angle = i + 30  # Rotate back
            time.sleep(0.004)

def sound(emotion):

04 // Sensor Input

TTP223 capacitive touch sensor on GPIO 17 and SW-420 vibration sensor on GPIO 22. Polling at 50ms intervals in a dedicated process.

# Sensor polling loop
touch_pin = 17   # TTP223
vibration_pin = 22  # SW-420

def check_sensor():
    while True:
        if GPIO.input(touch_pin) == GPIO.HIGH:
            q.put('happy')
        if GPIO.input(vibration_pin) == 1:
            q.put(emotion[randint(0,2)])
        time.sleep(0.05)

// Display Rendering Pipeline

The LCD driver uses Waveshare's ST7789V controller library. Images are loaded via PIL, converted from RGB888 to RGB565 format, and pushed to the display at 40MHz SPI clock speed for smooth animation playback.

# Frame rendering pipeline
def show(emotion, count):
    for i in range(count):
        try:
            disp = LCD_2inch.LCD_2inch()  # 240×320 @ 16-bit
            disp.Init()
            for i in range(frame_count[emotion]):
                image = Image.open(
                    '/home/pi/Desktop/EmoBot/emotions/'
                    + emotion + '/frame' + str(i) + '.png'
                )
                disp.ShowImage(image)  # RGB888 → RGB565 → SPI
        except IOError as e:
            logging.info(e)

// Main Event Loop

The main loop continuously checks the multiprocessing event flag. When triggered by the sensor process, it dequeues the emotion, terminates the idle animation, and spawns three parallel processes for display, audio, and motor control.

if __name__ == '__main__':
    p1 = multiprocessing.Process(target=check_sensor, name='p1')
    p1.start()
    bootup()                              # Startup sequence

    while True:
        if event.is_set():                # Sensor triggered?
            p5.terminate()                # Kill idle animation
            event.clear()
            emotion = q.get()             # Dequeue emotion

            p2 = Process(target=show,  args=(emotion, 4))
            p3 = Process(target=sound, args=(emotion,))
            p4 = Process(target=emotion_servo_fn)

            p2.start(); p3.start(); p4.start()
            p2.join();  p3.join();  p4.join()

        else:                             # No event → Idle
            p5 = Process(target=show,
                         args=('neutral', 4), name='p5')
            p6 = Process(target=baserotate,
                         args=(90, 60, 0.02), name='p6')
            p5.start(); p6.start()
            p6.join();  p5.join()

// Power Budget

Separate power domains prevent servo inrush current from brownout-resetting the Raspberry Pi. The PCA9685 V+ rail has its own dedicated external 5V supply.

Raspberry Pi 3B+ ~1.2A @ 5V
3× SG90 (peak) ~2.1A @ 5V
LCD + Sensors ~0.15A @ 3.3V

// Design Philosophy

EMO Robot was designed with a core philosophy of emotive minimalism — achieving rich emotional expression through the simplest possible hardware. Just two sensors and three servos create a surprisingly engaging companion that responds naturally to human interaction.

The 3D-printed shell uses a dual-color scheme (white body, blue accents) to evoke a friendly, approachable persona — critical for social robotics acceptance studies.
